# Vote B — Product / GTM (dissenting where Product overfits)

Seat: Voter B. Lean product/GTM, but Product’s Masthead-only / higher-ed-federation-only view is a Y2 story sold as Y1. WordPress and Skeptic are more true on gravity, wedge, and naming.

---

### M1
Vote: C
Confidence: 82
Why: D is the category error Skeptic named: WordPress is a labor market + hosting gravity well (41.1% of the web), not a feature checklist you out-ship from a Grappelli fork. A is hospice — honest for existing sites, not a company. B is a library, not a GTM motion. C is the only strategy that matches all three honest reports at once: extract the still-beating kernel (`Displayable` / `Page` / hostname multi-tenancy / processors / `{% editable %}`), leave TinyMCE 4 + `grappelli_safe` + Cartridge + Twitter in the museum, and ship a *new* product. WordPress is explicit: treat Mezzanine as reference architecture for typed pages, not the SKU that steals share. Python-CMS is explicit: do not become “Wagtail but smaller”; the empty cell is a shippable Django website. Product’s extract-and-rebrand instinct is right; its “Masthead is the company” packaging is premature (see M5). Extract models, not the CSS.

### M2
Vote: D
Confidence: 78
Why: Reject Product’s Year-1 ICP. “Director of Web, 30–300 properties, Campus $12–60k” is a real *whale*, not a beachhead. Product’s own 90-day plan does not ship federation, Campus SSO, or a Multisite migrator — those are month-12 items — so you cannot sell the federation OS in year 1. University procurement is an RFP; Wagtail already sits in that RFP (NASA/Google/NHS). A (freelancer Friday-site) is the Python-CMS *positioning* and has no ACV. C (agencies) is a channel, not a buyer: an agency will not bet a client brand on an unnamed CMS. D is the person WordPress already named as champion — “Python/platform engineer with a WP box they hate” — and the only Y1 buyer who can say yes without an RFP, install on current Django on Friday, and pay to get marketing off WordPress. Higher-ed comms directors are the Y2 land-and-expand *from* D (one campus marketing site → institute kit → federation), not the first invoice.

### M3
Vote: B
Confidence: 80
Why: Editor’s audit is damning and specific: the admin is Django ModelAdmin + frozen `grappelli_safe` + TinyMCE **4.1.10 (2015)** + a jQuery Tools yellow modal that reloads the page. That is not one HTMX pass away from 2026 (A). WordPress: “a Django-admin modernization is a museum project, not a WordPress strategy.” C (Sanity/Wagtail-like visual editor) walks into a house that is already occupied — Wagtail 7.4 StreamField, Sanity Studio — and Editor/Python-CMS both forbid cloning those UIs (no nested Gutenberg tree, no second React admin Mezzanine cannot staff). B is the product: Editorial Desk is what publishers touch (draft/review/schedule, assignments, a11y gate, grounded AI on typed fields); Django admin remains the data plane. Editor’s own close: authors almost never open ModelAdmin for pages/posts; kill the Admin/Site radio by making one chrome. That is Desk, not a StreamField clone.

### M4
Vote: A
Confidence: 86
Why: WordPress is the most evidence-based report in the room and it is not ambiguous: the *only* wedge that can steal share in 24 months is one-click WP migrate that preserves URLs/SEO **plus** AI-native authoring on *typed* content. Product’s 90-day list already includes the WP importer that preserves URLs; AI-native already specifies `MigrationJob` and Proposal-gated abilities (outline/draft/SEO/alt/migrate-from-wp). That is the offer you put on the homepage. C (federation OS) is a category narrative for Y2, not a wedge — and it is Product overfitting the whale. B (kits + Friday install) is how you *onboard* the Python shop, not why they leave WordPress. D (AI provenance/RAG OS) is what every CMS will claim the week WP 7.0 ships AI Client; it is a layer on typed fields, not the reason to switch. Lead with migrate + typed assist; kits and provenance ride along.

### M5
Vote: D
Confidence: 84
Why: This is the cleanest place to reject Product’s Masthead-only view. Skeptic: a fork inherits brand death; a new name is only legitimate as a real company with no “WordPress killer” slide. We do not yet have the company, the ten design-partner logos, or a name customers already use. Shipping “Masthead” (or “Nova”) before that is a press release, not GTM. Keeping “Mezzanine” (A) ships a compatibility museum to a market that already walked to Wagtail. Defer: working title on the repo and the preview tier, rename when the ICP can tell you the noun. Product’s “do not ship Mezzanine 6” constraint is still honored — we are not versioning the museum.

### M6
Vote: B
Confidence: 74
Why: Commerce is correct and Product’s “never Woo” is also correct. Cartridge is dead (PyPI 1.3.4, Django ≤4.1, Stripe broken since 2020); C is necromancy. A (none) leaves a hole WordPress listed under *must match*: a commerce *story*, not a Woo clone. Y1 is the affordance, not the engine: `catalog` as a page type (Category is already a Page, Product is already a Displayable — salvage that shape) + Stripe Checkout so the page you already wrote can take money. Order is a receipt. Never see a PAN. That is days, not a product line, and it serves the actual D-ICP (course-makers, NGO donate, museum ticket) without Utah-tax scope. Hard no on shipping plugins, PCI, and “WooCommerce replacement” marketing.

### M7
Vote: B
Confidence: 91
Why: Unanimous among Extensibility, Product, and WordPress, and it is the rare motion that is both principle and GTM. WordPress plugin hell is 69k plugins, 51.5% abandoned, 11,334 vulns in 2025 — that is the thing we steal *from*, not the thing we rebuild. Extensibility: Mezzanine extends like a Django project (Page subclass, processors, settings registry), has no install UI / sandbox / versioned hook surface, and must not grow one; the revolutionary path is typed capabilities + signed reviewed catalog, fifty packages, core batteries kept whole. Product: certified blocks in kits, signed manifests, no unsigned code. A (never marketplace) starves the kit/type surface that *is* the product. C (open marketplace) is a strategy to recreate the Automattic-vs-WP-Engine supply chain inside a Python process with no sandbox. Curated signed kits/types is the SKU.

### M8
Vote: B
Confidence: 83
Why: C (replace admin entirely in Y1) is a second product hiding inside the first: users, permissions, settings, comments, form entries, media, and every escape-hatch ModelAdmin. Editor does not ask for that — it asks that *authors* stop living in ModelAdmin, while a data admin can stay Django. A (admin forever) is the museum project WordPress already rejected and the 2012 skin Editor inventoried. B matches the actual Y1 staffing and the Product rule “editors never see Django admin” without lying about IT: superusers keep the hatch for types, migrations, and “I need a queryset.” Desk is the product; admin is the break-glass. That is also how you keep Python-CMS’s Django-native DNA without making Grappelli the roadmap.
